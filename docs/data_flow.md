## Internal Parts vs external Part1–12 runner

The main file defines and initializes its own internal `Part1`–`Part12` classes. It also conditionally imports selected external GPU/adaptor classes (for example `part2_FIXED`, `part7_FIXED`, `part8_FIXED`, and `part9_FIXED`) during optional setup. `run_all_parts.py` dynamically loads external `part*_FIXED.py` modules and has its own runner logic. These are **not interchangeable**: presence of `part1_FIXED.py`–`part12_FIXED.py` does not prove that `jarvis_FIXED.py` calls every external module, and imports alone do not prove initialization or decision impact.

## Static-audit safety boundaries

- `scripts/audit_system.py --offline` parses source, builds a bounded AST call/evidence graph, and runs only dependency-light helper probes in isolated subprocesses.
- `data-acquisition`, `symbol-selection-locking`, `normalization-indicators`, `fusion-final-veto`, `risk-contract-lots`, `execution-close-reconciliation`, `ollama-error-boundary`, `paper-isolation`, and `restart-reconciliation` are static-evidence categories. A regex/source hit produces `UNVERIFIED`, never a safety `PASS`; a hit count is a review index, not coverage or runtime proof.
- Narrow structural checks such as syntax parsing, selected entrypoint presence/guard, and runner distinction may pass based on their explicit static condition. They do not upgrade broad safety categories.
- Import reporting distinguishes known missing repository-local modules (`FAIL`), unavailable known optional/external modules (`SKIPPED`), and missing names that cannot be classified (`UNVERIFIED`). A clean local-import result is not asserted while names remain unclassified.
- A secret-like assignment scan is performed with values redacted. Candidates are `UNVERIFIED` and require review; absence of candidates is not credential validation.
- The auditor does not import `jarvis_FIXED.py` or `run_all_parts.py`, start threads, open feeds, call Ollama, use credentials, place orders, or run the arbitrary repository test suite.
- Dynamic imports, optional dependencies, generated code, real venue state, live/paper separation, restart/crash behavior, and Rust/Python parity remain coverage limitations.
