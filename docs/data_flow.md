## Internal Parts vs external Part1–12 runner

The main file defines and initializes its own internal `Part1`–`Part12` classes. It also conditionally imports selected external GPU/adaptor classes (for example `part2_FIXED`, `part7_FIXED`, `part8_FIXED`, and `part9_FIXED`) during optional setup. `run_all_parts.py` dynamically loads external `part*_FIXED.py` modules and has its own runner logic. These are **not interchangeable**: presence of `part1_FIXED.py`–`part12_FIXED.py` does not prove that `jarvis_FIXED.py` calls every external module, and imports alone do not prove initialization or decision impact.

## Static-audit safety boundaries

- `scripts/audit_system.py --offline` parses source, builds a bounded AST call/evidence graph, and runs only dependency-light helper probes in isolated subprocesses.
- It does not import `jarvis_FIXED.py` or `run_all_parts.py`, start threads, open feeds, call Ollama, use credentials, place orders, or run the arbitrary repository test suite.
- Findings are `PASS`, `FAIL`, `SKIPPED`, or `UNVERIFIED`. `SKIPPED`/`UNVERIFIED` are not silently counted as safety passes.
- Dynamic imports, optional dependencies, generated code, real venue state, live paper/live mode separation, and Rust/Python parity remain coverage limitations.
