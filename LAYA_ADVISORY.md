# Experimental Laya advisory integration

Laya is isolated from deterministic decisions. `_print_decision_audit` may publish separate advisory commentary after the final post-gate decision snapshot; the model must never set direction, confidence, sizing, entry gates, or order submission. The adapter worker is bounded to one in-flight request and audit never waits for inference.

Legacy Ollama routing in `jarvis_FIXED.py` is disabled: the former local HTTP helper is a no-network compatibility shim; the old options helper returns the observed-chain deterministic signal without reusing cached model output; the active DeepSeek validation gate was removed as an AI gate, leaving deterministic decision generation and downstream deterministic risk/entry/ownership/freshness checks authoritative. These changes do not establish whole-repository migration: Parts 1–12, standalone utilities, other entrypoints, imported integrations, and option helpers outside this file have not been comprehensively audited or converted. Do not claim all Ollama use is removed until that audit and migration is completed.

Laya's upstream Python API has `Router.predict(state, questions, ...)`; structured choice responses provide `answers[question_id].choice` and confidence. It is a general-purpose model with no established market validation. No inference or checkpoint download has been performed. `JARVIS_LAYA_ADVISORY=true` enables optional commentary (set false to disable); dependency/model unavailability must never act as approval or veto.

Offline checks run: `python -m py_compile jarvis_FIXED.py jarvis_laya_advisor.py`; `python -m unittest -v test_jarvis_laya_advisor.py test_jarvis_laya_runtime.py` (8 passed). These tests cover adapter isolation, not full live-path behavior. No exchange connection, live order, or deployment was used.
