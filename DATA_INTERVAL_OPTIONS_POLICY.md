# Market-data policy (initial, not backtest-optimized)

## Candle frames

The selected live analysis route requests all Binance Spot native Kline intervals: `1s`, `1m`, `3m`, `5m`, `15m`, `30m`, `1h`, `2h`, `4h`, `6h`, `8h`, `12h`, `1d`, `3d`, `1w`, `1M`. `1m` and `1M` are distinct. Closed-bar history targets are defined in `binance_timeframes.py`; one latest forming candle is kept separately and is never sent to indicator calculations. Current candle metadata refreshes through REST on the configured cache cycle (default 5 seconds); this change does not claim a Binance WebSocket feed. The short interval is a conservative freshness setting, not a verified per-symbol rate-limit optimum.

Every timeframe is passed to Parts 1–10 after all closed bars are truncated to the latest completed `1m` close. This prevents faster frames (especially `1s`) from leaking later bars into the same decision. The separate forming candle remains available as unconfirmed snapshot context; it is not indicator evidence or a confirmed trading signal. Higher-timeframe confluence first averages within five correlation groups, then weights the groups; correlated intervals are not independent votes. The legacy requirement that `1m` must itself signal remains. Part 7 validates and gates all supplied frames. The history counts and group weights are an initial engineering profile, not a measured optimum; validate with native, fee/slippage-aware Jarvis backtests before changing them.

Selected live candles are strict Binance Spot only. No Bybit perpetual, Delta fallback, resampling, padding, or implicit USD-to-USDT symbol conversion is accepted. Delta remains the intended execution/options venue. **The ordinary live loop does not yet pass the complete native MTF approval bundle into the protected Delta order path, and Binance Spot analysis is not yet bound to an exact Delta perpetual product, quote, quantity, and risk plan. Consequently, new entries must remain blocked; do not weaken broker-side checks to enable them.** These product mapping and quote/risk integration gaps, live exchange alignment, and feed availability require offline tests and orderless runtime verification before any live enablement.

## Options observations

Current listed expiries are current observations, not future price forecasts. Historical options replay reads only timestamped snapshots captured from providers; it never derives options history from candles. By default, snapshots are sampled at most every 300 seconds to `.jarvis_state/options_snapshots.jsonl`, rotated at 128 MiB per generation (three older generations retained). Set `JARVIS_OPTIONS_SNAPSHOT_PATH` to a persistent-volume path and `JARVIS_OPTIONS_SNAPSHOT_INTERVAL_SECONDS` / `JARVIS_OPTIONS_SNAPSHOT_MAX_BYTES` to tune storage. Historical coverage starts only after collection begins and only for assets actually queried; no pre-existing archive is implied.

Laya is optional, disabled unless `JARVIS_LAYA_ADVISORY=true`, and may provide commentary only at the final audit stage. It must not change direction, confidence, risk gates, targets, sizing, or orders. This is not a migration of every legacy Ollama/DeepSeek compatibility or deprecated code surface to Laya; those legacy names/paths are retired and must not regain authority. Laya runtime/package availability has not been verified.
