# Options-chain implementation notes (offline change)

## Provider acquisition and chain evidence

- Delta's public ticker path now follows advertised `after`/`next_cursor` or `has_more` pagination markers up to 100 pages. Missing terminal evidence, a repeated cursor, invalid response schema, provider error, or the page cap makes the chain incomplete/unusable. It requests a 500-row page size; the actual provider's behavior and cap still require production read-only verification.
- The optional read-only Binance Options adapter uses public `eapi` exchange-info, mark, and ticker endpoints. It reconciles each BTC/ETH option symbol in the listing manifest against both market-data symbol sets. If the endpoints or payload shapes are unsupported, it reports unavailable/incomplete; it does not create an empty complete chain. This adapter was not live-probed in this task.
- Delta and Binance remain separate in `providers`; normalized records from both venues are exposed, but cross-venue OI/PCR/IV is not added together. BTC/ETH and any additional Delta-listed selected asset are normalized by the same rules.
- Per-contract identity, positive strike, call/put type, expiry, and provider timestamp are checked. Freshness defaults to 600 seconds. A missing provider timestamp is `unknown`, not current. Expired rows are excluded and counted. Completeness and freshness failures do not become neutral, usable evidence.
- Quotes, IV, OI, volume, and delta/gamma/theta/vega/rho are retained if observed. Missing values remain `null` and each contract lists missing fields. Greek/IV/price units are explicitly provider-native/unverified. `greeks_model_derived` is always false; no Greek is inferred or filled. The provider payload must supply a value and timestamp to count it as observed.

## Descriptive calculations and strategy boundary

- PCR is computed only from a provider-local chain with complete observed OI. The pre-existing simple per-expiry PCR cutoffs remain the selected-asset Part14 heuristic; macro BTC/ETH data is not turned into a weighted directional vote.
- Max pain is now the listed strike minimizing aggregate intrinsic call-plus-put OI payout, not the largest-OI strike. It is reported in normalized `OI contracts × underlying price units`; one common unit contract multiplier is assumed only when no multiplier exists. It is not represented as currency P&L. Unsigned OI never supplies dealer long/short gamma or gamma direction.
- IV skew uses the nearest observed absolute-25-delta call and put (only within 0.10 delta) and reports call-minus-put IV by expiry in provider-native units. Term structure uses the median IV at the nearest listed strike to a caller-supplied, timestamped spot, separately per expiry; without a same-time fresh spot it is unavailable. The present Delta wrapper supplies no spot to this calculation, so term structure normally remains unavailable unless a validated caller adds aligned input.
- The selected Part14 callsite now passes the actual routed symbol; Part14 accepts the selected-asset chain only after validation. The canonical snapshot applies a deterministic conservative altcoin filter only when both fresh, complete BTC and ETH macro chains unanimously oppose the candidate. No weights are used. Macro data never substitutes for selected-asset required evidence.
- The BTC-only Oracle's explicit altcoin block, ownership/symbol lock, reconciliation, sizing, and other execution safety gates were not changed. Thus safe live altcoin execution remains blocked pending an appropriately validated selected-asset forecast/source; this change does not claim to enable it.

## Historical data and verification boundary

- Setting `JARVIS_OPTIONS_SNAPSHOT_PATH` enables append-only normalized snapshots; persistence is opt-in and has no default data-file side effect. `options_snapshot_store.replay_snapshot` selects only a fresh recorded snapshot at or before a timezone-aware decision time, matching the underlying/venue and rechecking observation times and expiry. Future, stale, malformed, or absent rows fail closed.
- No historical options provider is integrated or verified. The store starts at first enabled capture; it does not backfill the past. OHLC/candles are never used to invent options or Greeks. Existing backtests remain isolated from live feeds; the replay helper is deliberately separate from the OHLC strategy engine until a timestamped options dataset and explicit integration contract exist.
- Tests use fixed offline fixtures, including the production Delta `{"bias":"NEUTRAL","score":0,"reasons":["No Data"]}` shape, sparse quotes/Greeks, two pages, multiple strikes and expiries, provider failure, truncation, stale/future/wrong-asset records, max-pain payout math, and selected Part14 source structure. They establish behavior of the local adapter/normalizer only.
- No exchange endpoint was contacted during this task. Actual live BTC/ETH coverage, Delta pagination semantics, Binance Options support, provider timestamps/units, and runtime credentials/configuration remain **UNVERIFIED**. The code has not been launched as a bot, no workflow was dispatched, no secret was read or disclosed, and no order API was exercised.
